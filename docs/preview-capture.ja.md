# プレビュー画像の自動出力

準備画面とPreview画面の左下にあるカメラボタンで、現在の撮影視点を記録します。記録済みのボタンには小さな緑の印が付きます。もう一度押すと、そのプレートの設定を上書きします。視点はプレートごとに1つで、準備画面とPreview画面で共通です。準備画面ではスライス前から記録・確認できます。

記録後に画面を回転・移動・拡大しても、撮影設定は変わりません。通常の「プロジェクトを保存」で3MFに書き込みます。設定の記録と削除はUndo／Redoに対応し、印刷設定やツールパスを変更しません。

カメラボタンを右クリックすると、撮影設定ウィンドウが開きます。左側に記録した視点からの確認画像、右側に「スライス前のモデル／スライス後のツールパス」の画像切り替えと画像比率と出力幅・高さ（ピクセル数）を表示します。メイン画面も並行して操作できますが、ウィンドウの対象は開いたときのプレートに固定されます。

比率は「記録時」「1:1」「4:3」「3:2」「16:9」「9:16」「自由」から選べます。固定比率では幅・高さが連動し、縦方向の写る範囲を保って左右の範囲を変更します。解像度を変更してもカメラ位置や構図の縦方向は変えません。出力サイズは各辺1〜16384ピクセル、合計6400万ピクセル以内です。GPUによっては、これより小さい上限があります。

変更は「適用」で撮影設定へ反映します。「閉じる」は未適用の変更を破棄します。適用はUndo／Redoに対応し、再スライスしません。ウィンドウには「現在の視点を記録」「記録した視点に戻す」「撮影設定を削除」「PNGを書き出す」もあります。PNGは確認中の設定で出力でき、未適用の設定はプロジェクトや自動出力には反映しません。

スライス前の画像はモデルから描画し、スライス結果を必要としません。スライス後の画像はスライス完了後に更新します。処理中・スライス結果無効時は更新待ちを表示し、以前の画像が残る場合があります。記録したカメラ位置はメイン画面の視点操作には追従しません。「現在の視点を記録」は、対象プレートをメイン画面で選択しているときに操作できます。プレート削除・並べ替え・プロジェクト切り替え・Undo／Redoで対象が置き換わる場合はウィンドウを閉じます。

左下のハンバーガーメニューの「撮影ボタン」でカメラボタンの表示を切り替えられます。表示設定はアプリに保存されます。非表示にしても記録した撮影設定や自動PNG出力は維持します。カメラは他のボタンと同じ丸背景のアイコンで、記録済みの場合は小さな緑の印を表示します。

CLIでは、撮影設定のあるプレートをスライスすると、G-codeと同じ場所に `<G-code名の拡張子を除いた部分>.unsliced.png`（スライス前のモデル）と `.sliced.png`（スライス後のツールパス）の2枚を自動保存します。例えば `plate_1.gcode` に対して `plate_1.unsliced.png` と `plate_1.sliced.png` を生成します。

GUIの「G-codeをエクスポート」でも、撮影設定を記録したプレートはG-codeの保存成功後に、同じフォルダーへ `.unsliced.png` と `.sliced.png` の2枚を自動保存します。スライスだけを実行した場合は保存しません。撮影設定がない場合はG-codeのみを保存します。画像生成に失敗した場合は警告通知を表示し、G-codeは保持します。

```sh
OrcaSlicer --slice 0 --outputdir /tmp/sliced project.3mf
```

2枚とも画像を必要としない実行では、`--no-export-preview` を付けます。

```sh
OrcaSlicer --slice 0 --no-export-preview --outputdir /tmp/sliced project.3mf
```

両PNGには、共通の記録した位置・角度・投影方式・倍率・ピクセル寸法で3D表示を描画します。スライス前は対象プレートの印刷対象モデルをフィラメント色で描画し、モディファイアや操作用の表示物は含めません。スライス後はLine Typeの色分け、全レイヤー、すべての押出種別とSeamsを表示し、Travel／Wipe／Retract／Unretractは非表示にします。背景、ベッド、シェルも含みます。凡例、スライダー、操作用マーカーは含みません。

撮影設定は3MF内の `Metadata/orca_preview_capture.json` に保存します。印刷設定やプリセットには追加しません。カメラ位置・注視点はプレート原点からの相対座標です。組み込みベッドのアセットパスはリソースディレクトリからの相対パスで保存します。外部のカスタムベッド画像・モデルを使う場合は、そのアセットも実行環境から参照できる必要があります。

CLIの描画にはOpenGL 3.2以上と、GLFWがコンテキストを作成できる環境が必要です。画像生成に失敗した場合はプレート番号と理由を警告し、生成済みG-codeは保持します。PNGは一時ファイルへの書き込みが完了した後に置換します。失敗した場合、以前の同名PNGが残ることがあります。

## 移植元と修正点

`OrcaSlicer-DynaPin` の `4b4943e9d5` を基に、通常の OrcaSlicer の描画処理と GLAD に合わせて移植しました。DynaPin オーバーレイは本フォークにはありません。撮影メタデータの `dynapin` フィールドは互換性のため保持し、新しく記録する設定では無効にします。

参照元で確認した次の問題を修正しています。

- macOS／Linux の共通ファイル置換関数が旧 PNG を先に削除し、置換に失敗した場合に旧画像を失う。撮影画像では同じディレクトリの一意な一時ファイルへ書き終えた後、旧画像を事前削除せずに置換します。同時出力が同じ一時ファイルを共有する問題も避けます。
- 未スライス画像が、現在選択しているプレートに応じて変わる `print_volume_state` を参照する。対象プレート自身の造形範囲と明示的な印刷対象フラグで判定し、別プレートの選択によって撮影対象が消えないようにします。

## 検証方法

`tests/libslic3r/test_preview_capture.cpp` はメタデータの検証・シリアライズ・旧形式と不正メタデータを含む 3MF 読込を確認します。`tests/slic3rutils/test_preview_capture.cpp` はカメラ復元・比率変更・PNG 置換を確認し、明示的に指定する OpenGL テストで未スライスモデルとスライス後の描画を確認します。

```sh
cmake --build build/arm64 --config Release --target OrcaSlicer libslic3r_tests slic3rutils_tests --parallel 2
build/arm64/tests/libslic3r/Release/libslic3r_tests.app/Contents/MacOS/libslic3r_tests '[preview_capture]' --order rand --warn NoAssertions
build/arm64/tests/slic3rutils/Release/slic3rutils_tests.app/Contents/MacOS/slic3rutils_tests '[preview_capture],[.preview_capture_render]' --order rand --warn NoAssertions
```

OpenGL テストにはデスクトップの描画サービスへ接続できる環境が必要です。GUI の操作確認では、準備画面とプレビューの視点記録・設定変更・復元・削除・Undo／Redo・3MF 再読込・PNG 出力を確認します。撮影設定を持つ 3MF を CLI でスライスし、GUI と CLI で保存される画像の構図・寸法・色を比較します。`--no-export-preview` の場合と G-code・統計が変わらないことも確認します。

## 今回の検証結果

macOS arm64 の Release ビルドが成功しました。メタデータの 5 ケース・150 assertions、カメラ・PNG・OpenGL 描画の 5 ケース・86 assertions が `--order rand --warn NoAssertions` 付きですべて通過しています。

CLI の同一 3MF 入力について、自動画像出力あり・`--no-export-preview` の両方で、変更前の Release 版と G-code（生成日時の行を除く）・統計 JSON が一致しました。出力無効時は PNG を生成せず、存在しないベッドアセットを指定した失敗時は画像ごとに警告して G-code を保持しました。

GUI で保存済み撮影設定のある 3MF を読込・保存し、メタデータが変わらないことを確認しました。GUI からスライス・G-code エクスポートすると 2 枚の PNG を生成し、保存した 3MF の CLI 出力と画像寸法（1000 × 563）・構図が一致しました。未スライス画像は全画素一致、スライス後画像は 563,000 画素中 43 画素に最大 8/255 の差がありました。

実行テストで、移植先の `GLModel::init_from()` が GUI 設定を無条件に参照して CLI 描画時にクラッシュすることも確認し、GUI がない場合は既定のフラット法線を使うよう修正しました。GUI の既存設定による描画は維持します。

GUI 操作ツールの座標クリックが `windowNotFoundAtPosition` で失敗したため、撮影ダイアログでの視点記録・復元・削除・比率適用・Undo／Redo・プレート切替の一連の手動確認は未完了です。カメラ計算・保存形式・描画の自動テストとコードレビューは実施済みです。Windows／Linux のビルド・実行は未確認です。
